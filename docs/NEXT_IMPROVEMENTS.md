# linktive 후속 개선과 배포 점검

## 반영한 개선

- 북마크 목록에서 컬렉션 확인, `Q`로 사이트 추가, `Delete`로 삭제 확인
- `is:archived`와 `-is:archived` 검색, 확장 설정에서 Chrome 웹 스토어와 GitHub 열기
- 2단계 인증 등록·교체 재인증, 선택 가능한 최초 설정 토큰과 프록시 설정
- 북마크 공간 이동, 동시 편집 충돌 확인, 비공개 보관본이 있는 선택 항목 안내
- 재수집 시 이미지·CSS 로컬 사본 재사용, 자동 백업 실패 표시와 DB만·전체 백업 범위 선택, 엑셀용 CSV 내보내기
- 가입 언어 저장, 초기 설정 토큰과 비밀번호 표시 전환, 로그아웃 후 홈 이동, 계정의 직접 탈퇴
- 소스에서 빌드한 확장의 한국어·영어 UI와 저장한 소속의 북마크 상세 바로 열기

## 배포 전에 확인

1. 운영 서비스를 정지한 뒤 `data` 전체를 접근이 제한된 위치에 백업합니다. DB와 `assets`가 들어 있는 같은 시점의 사본으로 별도 컨테이너를 띄워 로그인과 기존 본문·이미지를 확인합니다.
2. 프록시를 쓰는 설치에서는 앱 포트의 공개 범위와 신뢰할 프록시 주소를 확인합니다. 새 서버를 외부에 공개할 때는 첫 등록 전에 초기 설정 토큰을 설정합니다.
3. 웹 목록, 단축키, 공유 권한, 확장 저장, PDF 출력 결과를 확인하고, 릴리스 태그와 웹 화면의 버전이 일치하는지 확인합니다.

## 확인 결과

- 시험용 이전 버전 데이터 전체를 복사한 뒤 새 버전에서 로그인과 기존 보관 본문·이미지를 확인했습니다.
- 관리자 화면에서 만든 전체 백업 ZIP으로 시험 서버를 복원해 로그인 세션, 보관 HTML, 이미지·CSS 원본을 확인했습니다.
- Chromium에서 목록, 단축키, 아카이브 검색, 확장 설치·저장, PDF 인쇄 시작을 점검했습니다.
- `v0.5.0` 후보에서 가입 언어 유지, 관리자 화면 로그아웃 후 일반 가입, 비밀번호 변경, 2단계 인증 설정·교체·해제, 회원탈퇴 및 API 키 폐기를 확인했습니다. 웹 기본 소속과 확장의 저장 소속을 다르게 지정한 상태에서 확장이 실제 저장 위치의 북마크를 여는 것도 확인했습니다.

## 남은 작업

- 운영 백업을 별도 컨테이너에서 주기적으로 복원해 검증하는 절차를 자동화합니다.
- 이전 버전에서 보관해 리소스별 기록이 없는 페이지는 실패 시 마지막 성공본을 유지합니다. 기존 페이지를 성공적으로 다시 저장하면 이후 실패한 리소스에 로컬 사본을 사용할 수 있습니다.
